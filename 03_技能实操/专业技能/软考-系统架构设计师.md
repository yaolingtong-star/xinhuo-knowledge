## 1. 架构设计基础

### 1.1 软件架构风格

| 风格 | 特征 | 适用场景 |
|------|------|----------|
| 分层架构 | 清晰职责分离 | 企业级应用 |
| MVC架构 | Model-View-Controller分离 | Web应用 |
| 微服务架构 | 服务拆分、独立部署 | 大规模互联网应用 |
| 事件驱动架构 | 松耦合、异步 | 实时系统 |
| 云原生架构 | 容器化、弹性伸缩 | 云平台应用 |

### 1.2 架构设计原则

**SOLID原则**
- 单一职责（SRP）：一个类只有一个变化原因
- 开闭原则（OCP）：对扩展开放，对修改关闭
- 里氏替换（LSP）：子类可以替换基类
- 接口隔离（ISP）：客户端不应依赖不需要的接口
- 依赖倒置（DIP）：依赖抽象而非具体实现

**其他核心原则**
- 高内聚低耦合
- 关注点分离
- 适度复杂（KISS）
- 延迟设计（Design Last）

## 2. 系统设计模式

### 2.1 分布式系统

**CAP定理**
- Consistency（一致性）：所有节点数据一致
- Availability（可用性）：每次请求都能获得响应
- Partition Tolerance（分区容错）：系统在网络分区时仍能运行
- 定理：三者不可兼得，只能在C和A之间权衡

**BASE理论**
- Basically Available（基本可用）
- Soft state（软状态）
- Eventually consistent（最终一致）

### 2.2 一致性算法

**Paxos**
- 解决分布式一致性问题
- 多数派决策

**Raft**
- 相比Paxos更易理解和实现
- Leader选举+日志复制

## 3. 系统性能

### 3.1 性能评估指标

| 指标 | 含义 |
|------|------|
| 响应时间 | 从发出请求到收到响应的时间 |
| 吞吐量 | 单位时间处理的请求数（TPS/QPS） |
| 并发用户数 | 同时发起请求的用户数量 |
| 资源利用率 | CPU/内存/磁盘/网络的利用程度 |

### 3.2 性能优化方向

- 数据库优化：索引、读写分离、分库分表
- 缓存策略：多级缓存、缓存失效策略
- 负载均衡：Nginx、LVS、CDN
- 异步处理：消息队列、线程池
